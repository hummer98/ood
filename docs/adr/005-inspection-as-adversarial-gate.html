ADR 005 — Inspection is an independent, enforced gate

Status: accepted · foundational

Context

An implementer judging its own work is biased: it tends to confirm that what it built is what was asked. The more capable the model, the more convincingly it rationalizes — so generation bias gets worse, not better, as models improve. Verification therefore must be (a) independent of the author and (b) enforced, not optional.

Decision

Inspection runs as a separate teammate context whose oracle is the plan's acceptance criteria. It writes a GO/NOGO report; the completion gate hook (ADR 003) blocks completion until that report says Verdict: GO.

sequenceDiagram
  participant I as implementer
  participant N as inspector (separate context)
  participant K as hook (gate)
  participant D as docs/reports
  I->>N: hand off (don't self-certify)
  N->>D: NNN-inspection.html · Verdict GO/NOGO
  I->>K: request completion
  K->>D: Verdict GO present?
  K-->>I: no GO → block (exit 2)

Consequences

  • Catches plausible-but-wrong work that a self-check would wave through; the gate makes verification non-skippable.
  • Costs an extra agent/context. Requires testable acceptance criteria upstream — the design-reviewer's job is to reject vague ones, or inspection has no oracle.

Alternatives considered

  • Implementer self-check — rejected: generation bias.
  • Human-only review — rejected: doesn't scale to every task and isn't enforced by the workflow.
