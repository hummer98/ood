ADR 004 — HTML, diagram-first documents

Status: accepted · foundational

Context

OOD documents serve two audiences at once: humans who decide and approve, and AI teammates who load them into context. Their optima differ — humans parse pictures fast; agents parse structure. We also want a single source per document, to avoid the Markdown↔HTML drift OOD exists to escape.

Decision

HTML is the standard format, one file per document (no Markdown source), and documents are diagram-first (Mermaid / inline SVG) — sequence, flow, architecture, state — with prose in support, not the reverse.

Consequences

  • Renders directly in a c11 browser/markdown surface; diagrams carry structure that walls of text bury. One source, no view to keep in sync.
  • HTML is heavier for AI context than terse Markdown → mitigate by keeping AI-read docs (adr, specs) semantic with minimal styling.
  • Mermaid loads from a CDN → for fully offline/static figures, use inline SVG.

Alternatives considered

  • Markdown source + generated HTML view — rejected: two artifacts that drift; reintroduces the sync problem.
  • Markdown only — rejected: weaker for human visualization and for embedding rich diagrams as the primary content.
